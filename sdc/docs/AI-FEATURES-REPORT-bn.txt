SDC — Skilleddesk Code: ইন্টেলিজেন্ট ও এআই ফিচার বিশ্লেষণ রিপোর্ট

তারিখ: ১৬ অক্টোবর ২০২৬ · সংস্করণ: SDC 2.0.4 (sdcd)


১. সারসংক্ষেপ

SDC একটি local-first coding-agent workbench: Tauri 2 ডেস্কটপ অ্যাপ (React + TypeScript), Rust-এ লেখা host daemon sdcd, একটি append-only event log এবং SDCP প্রোটোকল। এই রিপোর্টে প্রজেক্টের কোড, প্ল্যান ডকুমেন্ট, চেঞ্জলগ ও বেঞ্চ রিপোর্ট পড়ে সব ইন্টেলিজেন্ট/এআই অংশ এক জায়গায় সহজ ভাষায় সাজানো হয়েছে।

- প্রজেক্টের মূল ভিশন: “AI coding-এর Trust Layer — real server-এর জন্য, যেকোনো ভাষায়।” স্লোগান: Prompt the work. Watch the proof. Protect the server.
- বুদ্ধিমত্তা ১২টি স্তরে ভাগ করা যায়: নিজস্ব এজেন্ট, ৫টি ইঞ্জিন অ্যাডাপ্টার, Intent Engine (যেকোনো ভাষা বোঝা), Voice, Pace/Orientation, Context, Continuity, Verify, Trust Kernel, Research, Ops/Agency এবং SDC Anywhere।
- সংস্করণ ২.০ (SDC-v3) এ যোগ হয়েছে প্রায় ৩০টি সুইচযোগ্য বুদ্ধিমান ফিচার: শেখা (recipe, lesson, memory), রাউটার, cascade, failover, crash-resume, প্যারালাল এজেন্ট, অটোমেশন ইত্যাদি।
- বেঞ্চে (DeepSeek-এ) প্রমাণিত: একই pass rate-এ খরচ প্রায় ২১% কম; Claude Code-এর তুলনায় ৬৫% কম (ছোট নমুনা)। “মান বেড়েছে” — এটা এখনো প্রমাণিত নয়।

২.১ Master Plan v3 — মূল সিদ্ধান্ত

- Trust Kernel: Time Machine, Verify, Guard rails, audit log, rollback আলাদা ফিচার নয়, একটি ভিত্তি-স্তর — প্রতিটি AI কাজ এর ভেতর দিয়ে যায়।
- Universal Intent Engine: যেকোনো ভাষা, আঞ্চলিক রূপ (সিলেটি, চাটগাঁইয়া…), romanized লেখা (Banglish, Hinglish, Arabizi) ও ভয়েস বুঝে Task Spec বানায়, ব্যবহারকারীর ভাষায় নিশ্চিত করে, তারপর প্রতি engine-এর জন্য আলাদা prompt বানায়।
- ৬ ধাপের pipeline: বোঝা → তৈরি → যাচাই → চালু → রক্ষা → প্রমাণ।
- Safe Deploy আগে আনা হয়েছে, কারণ agency-র আসল কাজ deploy ও rollback।
- 2.0 “Autonomous Agency”: Night Guardian, Takeover X-ray, shadow DB migration।
- নিরাপদ সংশোধন: রাতে AI নিজে production-এ patch চালাবে না — শুধু শেষ ভালো version-এ rollback করবে (policy-তে অনুমতি থাকলে)।

২.২ Kernel-এর ছয়টি অংশ

- Audit ledger — প্রতিটি কাজের hash-chain করা অপরিবর্তনীয় লেখা।
- Policy engine — policy-as-code (.sdc/policy.toml)।
- Verify engine — test/build/lint, SAST, secret, dependency scan, অন্য vendor-এর AI review।
- Time Machine — checkpoint, ফাইল ও কথোপকথন restore।
- Cost governor — খরচ, budget, runaway ধরা।
- Kill switch — এক কী-তে সব বন্ধ।

২.৩ SDC-v3 প্ল্যানের নিয়ম

- প্রতিটি v3 আচরণের নিজস্ব সুইচ আছে; সুইচ বন্ধ থাকলে SDC হুবহু v1-এর মতো চলে।
- Token বাঁচানোর কৌশলগুলো ডিফল্টে বন্ধ। প্রতিটি মডেলে আলাদা বেঞ্চ পরীক্ষায় Q3 নিয়ম পাস করলে তবেই সেই মডেলের জন্য চালু হয় (model-profiles.json — হাতে নয়, sdcd bench profiles লেখে)।
- Q3 নিয়ম: pass rate ১ পয়েন্টের বেশি কমবে না, McNemar p ≥ ০.১, খরচ-সাশ্রয়ের ৯৫% ব্যবধান শূন্যের উপরে।
- v3.maxQuality দিলে সব token কৌশল একসাথে বন্ধ হয়।

৪. SDC Agent — বিস্তারিত

লুপ: মডেলকে প্রশ্ন → উত্তরে text ও tool call → প্রতি call: card → checkpoint → permission gate → run → result → পরের message। মডেল tool call বন্ধ করলে কাজ শেষ। বিল ঠেকাতে আছে runaway detector (একই call বারবার), cost governor, Stop বাটন ও ঐচ্ছিক maxSteps।

৪.৩ Skills, Sub-agent, স্থানীয় মডেল

- Skills: .sdc/skills/<name>/SKILL.md (এবং .claude/.codex/.agents skills)। system prompt-এ শুধু নাম ও বর্ণনা যায়, পুরো ফাইল দরকার হলে পড়ে।
- Sub-agent: balanced/deep মডেলের turn-এ sub-agent একই provider-এর সবচেয়ে নতুন fast মডেল ব্যবহার করে, সর্বনিম্ন reasoning effort-এ, reads সমান্তরালে।
- স্থানীয় মডেল: Ollama, LM Studio, llama.cpp, llamafile, LocalAI, vLLM, SGLang, Jan, KoboldCpp — OpenAI-সামঞ্জস্য যেকোনো server। দুটি tool-calling dialect (Anthropic ও OpenAI-style) সমর্থিত।

৭. Verify, Research ও Ops


৭.১ Verify pipeline

- checks — প্রজেক্টের নিজের typecheck/lint/test/build (cargo, go, pytest সহ)।
- scans — secret, SAST, npm/pip/cargo/composer audit।
- review — অন্য engine শুধু diff পড়ে file:line সহ সমস্যা বলে; Intent Contract-এর acceptance criteria এক এক করে মেলায়।
check ফেল করলে review বাদ যায় (token বাঁচাতে)। ফলাফল: PASS / FAIL / NO_CHECKS / UNPROVEN।


৭.২ Research (/research)

প্ল্যান → ৩–৫টি সার্চ → sub-agent দিয়ে পেজ পড়া → [n] সোর্সসহ উত্তর। পেজ আনার আগে robots.txt মানা হয় (G37)।

১০. ইউজার ইন্টারফেস (যেখানে বুদ্ধিমত্তা দেখা যায়)

- kernel প্যানেল: IntentCard (Intent Contract), CostCenter/CostMeter, PolicyEditor, ProofTab, TrustChip, KillSwitch, MemoryDialog, Agency/Ops, VoiceButton, ResearchSettings, AgentSettings, AnywhereSettings।
- prompt এলাকা: ModelSelector/ModelDropdown (শুধু connected মডেল), slash কমান্ড (/plan, /research), ResearchCard, QuestionCard, PlanCard।
- right panel: Verify, Time Machine, Duel (একই prompt দুই engine-এ), Preview, Terminal, Console, Analytics।
- Workbench: Servers, Agents (প্যারালাল board), Inbox (অটোমেশন)।
- বাংলা সহ বহুভাষা সমর্থন: locales/bn.ts এবং আলাদা string ফাইল (agentStrings, kernelStrings, researchStrings, anywhereStrings)।

১০.১ Provider ও Engine

- Provider Hub: ৬টি flow (API key, subscription OAuth, Ollama, custom endpoint, registry, doctor); মডেল তালিকা live/cached/bundled লেবেলসহ।
- Duel: দুই engine-এ একই prompt; Session Bridge: turn চলাকালীন engine বদলালেও কথোপকথন হারায় না; Steer: চলমান turn-এ বার্তা পাঠানো।

১০.২ SDC Anywhere

দূর থেকে approval, chat, terminal ও preview। E2E এনক্রিপ্টেড relay (Cloudflare Worker + Durable Object + D1) শুধু ciphertext বয়ে নেয়। Passkey (WebAuthn), TOTP, magic link; approval envelope-এ action_hash; এক স্ক্রিন থেকে অন্য স্ক্রিনে হস্তান্তরে fence-সহ lease।

একই প্রম্পট Claude Code প্রায় ১ ঘণ্টায় শেষ করত, SDC-তে লাগত ১০–১২ ঘণ্টা। মাপা কারণ:

- window ধরা ছিল 128K, আসলে 393K — ঘন ঘন fold, prefix cache ভাঙা, একই ফাইল ১২ বার পড়া।
- parallel_tool_calls চাওয়াই হয়নি — ৬০% ধাপে একটাই call।
- DeepSeek V4 সবসময় high thinking-এ; sub-agent পরপর পড়ত।
- এক turn একটি permission-এর অপেক্ষায় ৭ ঘণ্টা ৪০ মিনিট আটকে ছিল (রাতে)।
১.০-এ এগুলো ঠিক হয়েছে; বেঞ্চ টাস্কে ২৫৫ s → ৪২ s পর্যন্ত নেমেছে (মডেল ও region বদলসহ)।
