# P0-12 — Speed baseline and Step Trace

**বাংলা সারাংশ:**
- **Step Trace** (`trace.rs`, SQLite `step_trace`): প্রতিটি মডেল-call-এ এক সারি — task/step id, model key, mode (pinned/local-rotation/local-only), tokens in/out, thinking tokens (আন্দাজ), TTFT, tok/s, wall time, verify ফল, cost, escalation কারণ। এক পটভূমি-thread লেখে (channel), তাই ধাপের খরচ শুধু channel-send: **প্রতি ধাপে < ১ ms** (test: ২০০০ ধাপ, গড় < ১ms)।
- **Speed Gate** (`sdcd bench speed BASELINE CANDIDATE`): single-step কাজের median ও p90 প্রতি মডেলে আগের release-এর সাথে; **৫%-এর বেশি ধীর হলে FAIL** (exit 1); যে প্রশ্ন Code Graph/git-এ উত্তর হয় (`zero_model = true`) তাতে model call **০** হতে হবে। **১০% কৃত্রিম ধীরতায় gate ফেল করে** (test)।
- **UI:** ডান প্যানেলে নতুন "Trace" tab (বাংলায় "ট্রেস") — প্রতি ধাপের সময়-bar (প্রথম token-এর অপেক্ষা বনাম লেখা), model, mode, token, verify ব্যাজ, cost।
- **মাপা speed baseline** (deepseek-chat, single-step, ৩৮ রান, `bench/baselines/2026-10-17`): **median 3.84 s, p90 5.86 s**; gate সেই baseline নিজের সাথে মিলিয়ে PASS।

## What changed
`trace.rs` + `trace/tests.rs` (new); `store/sqlite.rs` (migration `0202-step-trace`); `agent/mod.rs` (TTFT via a `FirstByte` stream wrapper, thinking-token estimate, one `trace::record` per loop call); `agent/dialect.rs` (`Reply.ttft_ms/thinking_tokens`); `verify/mod.rs` (verdict -> newest step); `sdcp/model_methods.rs` + protocol (`trace.list`); `bench/mod.rs` (`speed`), `bench/task.rs` (`zero_model`); `v3/mod.rs` (switch `trace.steps`, on); app: `TraceTab.tsx`, `rightPanel.ts`, `kernelIntents.ts`, strings en + bn.

## Tests
- Rust 11 new + 1 end-to-end: a real turn leaves two rows (TTFT >= 1 ms, mode `pinned`, model key, step ids) and with the switch off leaves none; verify verdict lands on the newest step; rate arithmetic; **recording < 1 ms/step**; timings = median/p90 of single-step runs only (a 20-step task excluded); gate passes at +4.5%, fails at +5.5%, fails on **injected +10%**, fails on a slow p90 tail alone, fails when a zero-model task made a call, and says "no baseline" instead of passing silently. `cargo test --lib`: **1008 passed, 0 failed**.
- App: typecheck, eslint, vitest 256, `protocol:check` (182 methods) green; a11y 0 violations.

## Problems found on the way

Fixed by excluding the toast strip from the comparison (documented in `UI-GUIDE.md`); 4/4 stable runs after; a tampered baseline still fails (21%).
2. The tab strip gained a tab, so all four baselines legitimately changed; re-approved after looking at the diff.

## Not done / honest limits
- "Speed Gate **in CI**": the gate and its exit code exist, but wiring it into the release workflow needs a baseline from the previous release plus an API key in CI secrets; that is part of P0-17's CI wiring. Until then it is run by hand: `sdcd bench speed <prev-baseline> <new-run>`.
- Escalation reason is always empty until the Rotation Chain exists (P2); `verify` is filled by Verify runs only.
- Thinking tokens are an estimate (characters/4) because providers differ in whether they report them; labelled as such in the UI.
- Cost uses the catalogue's price with cached input at 10% - the bench's own assumption, not a bill.
- Timeline view is a right-panel tab (the Workbench in the plan has no component yet); it re-reads every 4 s rather than subscribing.
