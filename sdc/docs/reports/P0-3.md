## How the split is done (and why it cannot change behaviour)

The house pattern already existed: `dispatch` is one big `match`, and the `_` arm hands the method on to the next
module (`kernel` → `intent` → `ops` → `agent` → `anywhere`, at the end). The six new modules are the same shape -
`use super::*;`, an `impl Daemon`, a `dispatch_<domain>` that falls through to its neighbour - so the chain is now

```
dispatch → host → workspace → file → model → guard → fleet → kernel → intent → ops → agent → anywhere
```

Two facts make this a move and not a rewrite:

1. **The arms are matched by exact string.** An arm lifted out of `dispatch` into a child still matches the same
   method name, and the chain only consults one arm per method, so even a badly bucketed arm would behave the same.
   The only edit to `dispatch` is `_ => self.dispatch_kernel(...)` → `_ => self.dispatch_host(...)`.
2. **A child module can reach its parent's privates.** `root_for`, `remote_for`, `subject`, `host_id_for` and the
   rest of the private helpers stayed in `methods.rs`; `kernel.rs` and the new children call them as before. The
   handlers that moved became `pub(super)` - the only text the move changes - so a sibling and the parent's
   `dispatch` can still call them. A handler that was already `pub`/`pub(crate)` kept its visibility (this is what
   `v3::run` needs from `run_automation`).

binary over a socket, so the moved handlers (including `host.shutdown`) are exercised end to end.

## The five facades

`runtime/`, `sme/`, `precision/`, `rotation/` and `guard/` are **empty on purpose**: each `mod.rs` says which task
fills it and where that code lives today (`crate::agent`, `crate::v3::router`, `crate::trust::policy`, …). P0-3
creates the seam so P0-4 onwards can add step machinery without a second reshuffle of `agent/mod.rs` after those
changes land.

## Switch / risks
Switch: n/a. Risk: `use super::*;` in six modules narrows nothing at compile time but does mean a helper added to
`methods.rs` becomes reachable from all six - the same trade-off `agent_methods.rs` already accepted. Nothing in this
task was measured against a model, so no bench number moved.
