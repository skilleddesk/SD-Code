## What this pins (the point of the task)
`permission_gate`, `policy_and_cost`, `engine_wire_formats`, `native_api_request_shape`, `verify_plan_and_verdict`,
`ledger_chain_and_audited_events`, `token_technique_profile`, `search_speed_and_ranking` and the P0-1 model bench all
read the same behaviour through the public API and compare it to a golden file, so a refactor that silently changes a
default (a risk level, a price, a header, a SQL shape) fails a test instead of shipping.

One finding, recorded rather than fixed: **the ledger's head hash is not a function of the events alone** — each row
carries its own write time, so two ledgers fed identical events end with different heads. Both verify as intact. The
test documents this; changing the hash would invalidate every ledger written so far, so it is not this task's call.

## File-search guard
The plan expected a failing perf test (the v1 walk, 227–261 ms per query over 52,501 files). That walk is already gone
(W3's watched index), so the guard asserts the new reality instead: a listing over a 4,000-file tree stays under
100 ms per call. It fails if a per-query walk ever comes back.

## Switch / risks
Switch: n/a. Risk: the baseline is one model on one machine (macOS aarch64). `bench/baselines/` is the reference every
later comparison reads; a second freeze of the same name is refused unless `--force`.
