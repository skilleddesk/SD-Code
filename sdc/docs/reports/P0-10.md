# P0-10 — Model-selection contract, ModelGate and Pin Guard

**বাংলা সারাংশ:**
- নিয়ম এক লাইনে: chat box-এ যে মডেল বাছা, সিদ্ধান্তও তার। ক্লাউড/API/CLI মডেল = **Manual Pin**: প্রতিটি call (loop, sub-agent, review) শুধু ওই মডেলে; router, cascade, failover, ladder, planner-executor, bandit **নাগালের বাইরে** (বন্ধ-করা সেটিং নয়, কোডে পৌঁছানোই যায় না)। লোকাল মডেল + chain-এর সারি = **Local Rotation**; লোকাল + খালি chain বা `privacy=local-only` = **Local-only**।
- কেন্দ্রীয় `ModelGate` (`guard/modelgate.rs`): প্রতিটি মডেল-call আগে gate-কে জিজ্ঞেস করে (`agent::ask_model` এর একমাত্র funnel)। অন্য মডেল চাইলে `PinViolationError`, নেটওয়ার্কে কিছুই যায় না।
- ব্যতিক্রম শুধু ব্যবহারকারীর নিজের লেখা সেটিং (`/research`-এর final model): gate-এ নাম ধরে, শুধু ওই মডেল ও ওই উদ্দেশ্যে।
- মোড ব্যাজ মডেল-বোতামের পাশে: **Pinned / Local Rotation (n) / Local-only** (বাংলায়: পিন করা / লোকাল রোটেশন (n) / শুধু লোকাল)।
- switch `models.contract` (ডিফল্ট চালু); বন্ধ = আগের সব সংস্করণের আচরণ (পুরনো failover/cascade test এখন এই switch বন্ধ রেখে চলে — এটাই "switch off = old behavior"-এর প্রমাণ)।

## What changed
`guard/modelgate.rs` (new); `agent/mod.rs` (`ask_model` takes the turn + purpose and asks the gate; `turn_gate`; sub-agent fast model, router, bandit, failover, cascade each ask `allows`); `v3/mod.rs` (switch); `sdcp/model_methods.rs` (`models.list.rotation.enabledRows`); `protocol/*` (+ `rotation`, `probe`); app: `store/model.ts` (`modelMode`), `ModelSelector.tsx` (badge), strings en + bn.

## Tests (all pass)
- guard::modelgate (7): mode follows the choice; a pinned turn permits its own model and refuses every other (incl. `deepseek/deepseek-chat` = same model); every automatic changer unreachable under a pin; local-only never leaves the machine, rotation may call a chain row *as a chain row*; only person-written exceptions pass, only for their model and purpose; switch off = open gate; a second registration inside a turn cannot replace the pin.
- agent end-to-end (2 new): with a failover order, a cascade strong model and a router fast model **all configured**, a pinned turn's three scenarios (provider refuses 401 / draft keeps failing / a plainly light question) send **only** the pinned model, and the "other model" listener is **never so much as connected to**; a forced foreign call raises `PinViolationError` and sends nothing.
- `cargo test --lib`: **990 passed, 0 failed**. App: vitest 256 pass, typecheck, eslint, `protocol:check`, visual (0.000%) and axe (0) all green.

## Problems found and fixed on the way
1. **`protocol:check` was broken by P0-3** (it scanned a fixed list of `sdcp/*.rs`; the six new modules were invisible, so it reported 40+ methods with "no arm"). It now scans every file in `sdcp/`. Would have failed CI.
2. **Two frontend tests I added in P0-9 failed `tsc -p tsconfig.node.json`** (they pulled DOM code into the Node-typed `tests/` folder). Moved next to the code they test.

## Limits (honest)
- The plan's "run all bench tasks in Manual Pin on 3 OS and assert the provider logs": done as the end-to-end test above on macOS; a paid full-bench run was **not** repeated for this task (the bench harness is unchanged and the pin is the default for it), and Windows/Linux are not run here.
- CLI engines (Claude Code, Codex, Gemini CLI) run their own agent loop inside the CLI; SDC cannot see or gate the models they use inside. They are one pinned engine from SDC's side.
- The badge reads the computer's Rotation Chain; a project that forces local-only via `.sdc/policy.toml` is enforced by the daemon whatever the badge says (the receipt in P0-15 will name the mode a turn really ran in).
- Chain rows (Purpose::Chain) are permitted by the gate in Local Rotation but nothing calls them yet: that is P2.
