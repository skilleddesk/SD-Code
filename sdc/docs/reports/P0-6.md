# P0-6 — sdcd local API hardening

**বাংলা সারাংশ:**
- daemon-এর দরজা এখন `src/guard/daemon.rs`-এ (P0-3-এ খোলা `guard/` seam-এর প্রথম বাসিন্দা): **per-client token**,
  **Host যাচাই** (DNS rebinding defence), **Origin যাচাই**, **rate limit**, আর **CORS wildcard নেই** — কোনোটাই।
- token এখন OS-এর random generator থেকে (৩২ বাইট, ৬৪ hex)। **`adopt`** দিয়ে যে token আগেই আছে (বুকমার্ক করা status link)
  সেটাও নেওয়া যায়, তাই প্রতি restart-এ নতুন লিংক হয় না; আর `revoke("status")` দিয়ে বাতিলও করা যায়।
- **আসল যাচাই (running daemon-এ, curl দিয়ে):**

  | অনুরোধ | ফল |
  |---|---|
  | সঠিক Host + সঠিক token | **200** |
  | `Origin: http://evil.example` | **403** |
  | `Host: evil.example` (rebinding) | **403** |
  | ভুল token | **403** |
  | token নেই | **403** |
  | `Host: 192.168.50.56:7813` (ফোনের লিংক) | **200** ← ফিচার ভাঙেনি |
  | উত্তরে `Access-Control-*` হেডার | **নেই** (ইচ্ছাকৃত) |

- ইউনিট test: `guard::daemon`-এ **১৪টি**; পুরো suite **৯৫৬ পাস / ০ fail**।

## কী বদলাল
- `sdc/sdcd/src/guard/daemon.rs` (নতুন), `guard/mod.rs`-এ `pub mod daemon`.
- `sdc/sdcd/src/status.rs`: status server এখন `Guard`-এর ভিতর দিয়ে যায় — `Host`/`Origin`/token যাচাই, LAN address
  নাম ধরে অনুমোদিত (তাই ফোন কাজ করে), আর উত্তরে `Referrer-Policy: no-referrer` যোগ। CORS হেডার এখনও নেই, এবং
  কোডে লেখা আছে কেন তা ইচ্ছাকৃত।

## চারটি যাচাই, ক্রমসহ (ক্রমটাই গুরুত্বপূর্ণ)
1. **token** — per client, replaceable, revocable। একটাই শেয়ার করা token মানে একটাই ফাঁস হওয়া token যা সবাইকে না ভেঙে
   বদলানো যায় না। token আগে যাচাই হয়, host পরে — যাতে LAN-এর স্ক্যানার দুই রকম উত্তরের পার্থক্য থেকে সার্ভিসের আকৃতি
   না শেখে।
2. **`Host`** — loopback (`127.0.0.1`, `127.0.0.0/8`, `[::1]`, `localhost`) বা ব্যক্তির অনুমোদিত নাম। DNS rebinding-এর
   পুরো প্রতিরক্ষা এখানেই: `127.0.0.1`-এ resolve হওয়া একটা নাম এখনও *এই কম্পিউটারের নাম নয়*।
3. **`Origin`** (থাকলে) — `Host`-এর সাথে মিলতে হবে। অন্য সাইটের পাতা token পেলেও এখানে আটকায়; `null` (sandboxed page)ও
   আটকায়, কারণ যে পাতা বলতে চায় না সে কোথা থেকে এসেছে, তাকে উত্তর দেওয়া হয় না।
4. **rate** — একই source টানা ভুল করলে আর দেখা হয় না (`REFUSAL_LIMIT = 20` / ৬০ সেকেন্ড)। এটা ৩২-বাইট token আন্দাজ
   আটকানোর জন্য নয় — একটা paid model call বা filesystem walk লুপে চালু হওয়া আটকানোর জন্য।

## দুটি বাগ যা আমি নিজেই লিখে ধরা পড়েছি
1. `host_without_port` প্রথমে `split(':')` করত, তাই `[::1]:7811` → `[` হয়ে যেত। এখন bracket ও port আলাদা করে, আর
   bare IPv6 (`::1`) তার কোলন ধরে রাখে।
2. non-loopback IP (যেমন অনুমোদিত `192.168.1.20`) `parse::<IpAddr>()`-এর early-return-এ আটকে যেত, অনুমোদিত তালিকায়
   পৌঁছাতই না — অর্থাৎ ফোনের ফিচার ভাঙত। ক্রম বদলে **আগে অনুমোদিত তালিকা, পরে loopback যাচাই** করা হয়েছে।

## সীমা (সৎভাবে)
- এটা firewall নয়: একই user-এর অন্য process keychain আর socket পড়তে পারে। P0-6-এর লক্ষ্য **ব্রাউজার** আর **hostname**-কে
  ব্যক্তির বিরুদ্ধে ব্যবহার করা — এই শ্রেণীর আক্রমণটাই বাস্তবে ঘটে।
- প্রমাণ শুধু macOS-এ। Windows/Linux-এ status server একই কোড, কিন্তু সেখানে চালিয়ে দেখা হয়নি।
- rate limit-টা status=403 দিয়েই হয়, তাই curl দিয়ে "rate" আর "token" আলাদা করা যায় না — সেটা unit test-এ পিন করা আছে।

## Switch / risks
Switch `daemon.secure`। ঝুঁকি: যেসব ক্লায়েন্ট `Host` হেডার পাঠায় না, তারা শুধু loopback transport-এ অনুমোদিত হয়
(unix socket / 127.0.0.1 থেকে TCP) — সেটাই বিদ্যমান CLI-এর পথ, তাই ভাঙে না; কিন্তু ভবিষ্যতে non-loopback transport
যোগ হলে তাকে `Host` পাঠাতেই হবে।
