# P0-8 — Local Runtime Guard

**বাংলা সারাংশ:**
- Ollama `num_ctx` ছাড়ালে নীরবে prompt-এর শুরু ফেলে দেয়। এখন প্রতিটি call-এর আগে SDC নিজে token গোনে (`guard/context.rs`, ইচ্ছে করে **বেশি** গোনে) আর window-এ না ধরলে **পাঠায়ই না** — `ContextOverflow` ফেরত দেয় যাতে কাজ ভাগ হয়।
- একই check সব cloud মডেলে (ক্যাটালগে ডকুমেন্টেড window থাকলে); যে মডেলের window অজানা তাকে বিচার করা হয় না (আন্দাজে সীমা বসানো হয় না)।
- উত্তরের পর `prompt_eval_count` মেলানো: window ভরে গেলে উত্তর বাতিল (`may have been cut`)।
- `/v1` কখনো নয়: test প্রমাণ করে Ollama-র URL `/api/chat` ও `num_ctx` সবসময় থাকে।
- switch `local.runtime_guard` (ডিফল্ট চালু); বন্ধ করলে পুরনো পথ — test দিয়ে প্রমাণিত।
- **Ollama-র সাথে আসল পরীক্ষা এই macOS-এ হয়নি** (ollama নেই) — নিচে আপনার জন্য হাতে-যাচাইয়ের ধাপ।

## What changed
`sdc/sdcd/src/guard/context.rs` (new), `agent/mod.rs::ask_model` (check before send, judge after), `v3/mod.rs` (switch).

## Tests (all pass)
- guard::context (7): estimate never under-counts; 2x-window prompt refused; fits-with-reserve; the answer's reserve counts; a count that fills the window or passes the estimate is invalid, a smaller one proves nothing (prefix cache); sentinel-at-start scenario; reserve rule.
- agent (3): 2x prompt never sent (address has no server; a sent request would fail with a connection error, not ContextOverflow) + switch off restores the old road; a full-window `prompt_eval_count` marks the answer invalid; Ollama is never reached via `/v1` and `num_ctx` is always set. The pre-existing tool-call test over `/api/chat` still passes.

## Design notes / honest limits
- The estimator is a bound, not a tokenizer: 3 ASCII bytes/token, 2 tokens per non-ASCII char, +8 per message, +16. It will sometimes refuse a prompt that would have fitted. `/api/tokenize` (exact count) is not used: Ollama has no such endpoint in the versions I could check offline; the plan says "when available" — the hook is `estimate_request`, which a probe-backed count can replace in P0-9.
- A *smaller* `prompt_eval_count` than expected cannot be treated as truncation: Ollama reports only newly evaluated tokens when it reuses a cached prefix. So only "at/over the window" and "over our own over-estimate" are flagged.

## How you verify by hand (needs Ollama + `qwen3.5:9b`)
1. `ollama pull qwen3.5:9b`; open SDC, pick the model, paste a ~60k-token file and ask a question about its first line: SDC should say `ContextOverflow` / split, not answer from the tail.
2. Ask a question whose answer is a word placed at the very start of a prompt just under `num_ctx`: it must be answered correctly.
3. `ps`/Ollama log: requests go to `/api/chat`, never `/v1/chat/completions`.
4. Settings → `v3.local.runtime_guard` off: the old behaviour returns.
