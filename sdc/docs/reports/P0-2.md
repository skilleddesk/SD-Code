# P0-2 — Keychain and Claude compliance

**বাংলা সারাংশ:**
- কী এখন **OS keychain**-এ যায় (macOS Keychain / Windows Credential Manager), প্লেইনটেক্সট ফাইল শুধু তখনই থাকে যদি কোনো
  store না পাওয়া যায় — আর সেটা 0600 permission-এ।
- মাইগ্রেশন **যাচাই করে তারপর মুছে**: কী store-এ লেখা হয়, ফেরত পড়ে মেলানো হয়, তবেই ফাইলটা ডিলিট হয়। store যেটা ফেরত দেয়নি
  সেটার ফাইল থেকে যায় (`failed`)।
- নতুন কমান্ড: `sdcd keys migrate [--apply]` (আগে দেখায়, `--apply` ছাড়া কিছুই মুছবে না) এবং `sdcd keys stray [DIR]`।
- Doctor-এ দ্বাদশ row যোগ হয়েছে — "API keys": কোন store সত্যিই ব্যবহৃত হচ্ছে এবং কতটা কী এখনো fallback ফাইলে আছে।
- **Claude compliance:** SDC আর Claude Code CLI-এর নিজের credential (OAuth token) পড়ে না বা এগিয়ে দেয় না —
  `src/engines/credentials.rs` মুছে ফেলা হয়েছে, আর একটি guard test ফাইলটা ফিরে এলে ধরে ফেলবে।
- যাচাই: `sdcd keys migrate` → `keys` খালি (এখন কোনো প্লেইনটেক্সট কী নেই), `auth::migrate`-এর ৩টি test ও doctor-এর ৩টি test পাস।

## What changed
- `sdc/sdcd/src/auth/migrate.rs` — the module existed but was **not wired into `auth/mod.rs`**, so nothing compiled it and
  nothing called it. Added `pub mod migrate;`, the `main` entry point, and `doctor_row()`.
- `sdc/sdcd/src/host/doctor.rs` — the twelfth check (`secrets`) + its test; the "exactly eleven" test was renamed to twelve.
- `sdc/sdcd/src/main.rs` — `sdcd keys …` is handled before the async runtime (like `plan` and `bench`), so a locked or
  missing key store is reported as a key-store answer rather than a daemon failure; the usage text lists both new commands.
- `sdc/sdcd/src/engines/cli.rs`, `engines/mod.rs`, `engines/credentials.rs` (deleted), `src/ssh/ops.rs` — the Claude
  compliance half, carried over from the earlier session, in one commit here.

## The rule that decides, and why
`migrate_dir` never deletes on a successful *write* alone: it writes, **reads back and compares**, and only then removes
the plaintext file. A store that silently truncates a key (the test's `lossy` case) leaves the file exactly where it was
and reports `failed`, so the person is never locked out of their own key by a store that lied.

## Measured
```
$ sdcd keys migrate          # this Mac, the shipped build (keychain feature on)
{ "apply": false, "keys": [] }
```
The `keys/` folder under the data directory is empty and mode 0700: there is no plaintext key left to move. The DeepSeek
key used by the P0-1 bench was written straight into the Keychain (`dev.skilleddesk.sdc` / `sdc.provider.deepseek`) and
was never printed.

`sdcd keys stray <dir>` reports `{path, rule, line}` and **never the value** — run against SDC's own source it finds
`auth/migrate.rs` and `trust/scan.rs`, which hold key-shaped *test fixtures* on purpose. Exit code 2 means "found something".

## Tests
`auth::migrate` (3): a key is deleted only after the store gives it back · without confirmation nothing moves · a key file
beside the code is reported by path, never by value.
`host::doctor` (3): exactly twelve checks with the five required fields · the keys row names the store that is really in
use · a missing tool is a fail row and not a panic.
`tests/credential_guard.rs`: the Claude CLI's own credential is not read and not forwarded.

## Switch / risks
Switch `secrets.keychain`: on for the shipped macOS/Windows builds (`app/scripts/package-daemon.mjs` decides), off on Linux,
where `keyring` v3 has no reachable store in a service account — those builds keep the 0600 file and the doctor row says so.
Risk: on a machine whose keychain is locked, `set` fails and the key stays in the file (by design); the doctor row is what
tells the person which of the two is happening.
